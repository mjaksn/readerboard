This crontab line is no longer needed. Remove it.

The service now keeps the sign's clock itself: at startup, once an hour, and
every time the link to the sign comes back. That last one is the part a crontab
line could never do. After a power cut the sign comes back with a wrong clock at
whatever moment the power returns, and this line would leave it wrong until the
next time minute 1 came round.

If you want to set the clock by hand, there is an endpoint for it:

    curl -X POST http://z2m:5001/v2/sign/sync-clock -H 'X-API-Key: YOUR-KEY'

Take the line out only after the new service is running and you have confirmed
the sign's clock is being kept. Until then it is harmless: it calls the same
compatibility endpoint it always did, and only needs the API key header added.

The line as it was, for reference. Note the added header:

  1 * * * * time_str=`date --date="next minute" +"\%H\%M"` && curl -X 'POST' 'http://z2m:5001/Write/ControlCommand' -H 'accept: application/json' -H 'X-API-Key: YOUR-KEY' -H 'Content-Type: application/json' -d '{ "command": "SET_TIME", "parameter": "'$time_str'"}'  #Update BetaBrite time
